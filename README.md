# EdTech Course Analytics using Power BI

**Type:** Self Project | **Duration:** Dec 2025 – Jan 2026

## Objective
Deliver category-wise insights from lecture/course data to identify growth opportunities and learner engagement patterns, using an end-to-end pipeline: Python data cleaning → SQL star-schema analysis → Power BI dashboard with DAX.

## Part 1 — Dataset
This project uses a **synthetic dataset** (`data/raw_data.csv`, 867 rows before cleaning / 850 after) generated by `python/generate_dataset.py`, built with:
- 8 categories × 34 subcategories (Development, Business, IT & Software, Design, Marketing, Personal Development, Photography & Video, Music)
- 9 languages, 500+ instructor names, 40 skills
- Realistic distributions (log-normal views weighted by category popularity, gamma-distributed durations, normal-ish ratings) plus **intentional messiness** — duplicate rows, inconsistent casing, comma/"k"-suffixed view counts, mixed date formats, missing values — so the cleaning step (Part 2) is genuine, not decorative.

**If you'd rather use a real public dataset:** the closest realistic substitute is a Udemy/Coursera course-catalog export on Kaggle (search "Udemy courses dataset" — several versions exist with columns like course title, subject, price, num_subscribers, num_reviews, level, and published date). Download the CSV, rename columns to match the schema below, and run it through `python/data_cleaning.py` (adjust column names in the script as needed) — the rest of the pipeline (SQL, DAX, dashboard) works unchanged.

**Schema (both raw and cleaned):**
`Course_ID, Course_Name, Category, Subcategory, Language, Instructor, Duration_Hours, Views, Ratings, Number_of_Reviews, Skills, Subtitles, Course_Level, Course_Price, Enrollment, Course_Date` (+ `Skill_Count, Course_Year, Course_Month, Views_Outlier, Duration_Outlier` added during cleaning).

## Part 2 — Data cleaning
See `python/data_cleaning.py`. Run:
```bash
python python/generate_dataset.py    # only needed if regenerating raw data
python python/data_cleaning.py
```
Every step (deduplication, text standardization, language mapping, instructor name cleanup, numeric coercion, category-median rating imputation, subtitle normalization, mixed-date parsing, IQR outlier flagging) is commented inline explaining the *why*, not just the *what*.

## Part 3 — Data model
See `documentation/data_model.md`. Star schema: `fact_courses` (grain = 1 row/course) + `dim_category`, `dim_instructor`, `dim_language`, `dim_level`, `dim_date`, all one-to-many, single-direction. Built via `python/build_star_schema.py` and documented as DDL in `sql/create_schema.sql`.

## Part 4 — SQL analysis
See `sql/analysis_queries.sql` — 18 business questions (total courses/views, top instructors, category/language distributions, duration-vs-views, skill engagement via a recursive CTE, subtitle impact, ranking with `RANK()`, and a high-demand/low-supply growth-opportunity query). All 18 have been run and verified against `data/edtech.db`.

## Part 5 — DAX measures
See `documentation/dax_measures.md` — ~18 measures (KPIs, ratios, share-of-total, Top-N text measures, `RANKX` leaderboards, `SAMEPERIODLASTYEAR` YoY growth), each with the exact DAX, what it calculates, and where it's used on the dashboard.

## Part 6 & 7 — Dashboard design & visuals
See `documentation/dashboard_design.md` — full 4-page layout (Executive Overview / Instructor Analytics / Course & Engagement Analytics / Market & Growth Opportunities) with a visual-by-visual spec table (type, axes, legend, tooltip, filters, rationale) for every chart.

## Part 8 — Business insights
See `documentation/business_insights.md` — 12 insights **calculated from the actual cleaned dataset** (not invented), e.g. IT & Software leads on engagement, duration/skill-count show ~zero correlation with views, subtitles carry a real engagement premium, Development and Marketing are under-supplied relative to demand.
